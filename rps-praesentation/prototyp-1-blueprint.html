01 · SPIELSTAND

V1 speichert die Punkte im Spiel – doppelt, je Spieler ein Attribut. V2 legt sie in den Spieler: jeder kennt seine eigenen Punkte.

02 · BEZIEHUNG

V1: gerichtete Assoziation – das Spiel kennt spieler01 und spieler02 dauerhaft. V2: keine Assoziation, Spieler werden nur an spielStarten(pS1, pS2) übergeben.

03 · SIEGER

siegerErmitteln() liefert in V1 das Spieler-Objekt, in V2 nur einen String.

AUFFÄLLIG

In beiden Diagrammen steht bei Spieler + Spiel() – gemeint ist der Konstruktor Spieler().

REGEL

Get, wenn eine andere Klasse den Wert lesen muss (Anzeige, Auswertung). Set nur, wenn er von außen geändert werden muss – sonst bleibt das Attribut gekapselt. Kein setAktSymbol(): das erledigt symbolUebermitteln(). In V2 braucht das Spiel Setter für die Punkte im Spieler.

Aufgabe c · Beurteilen

Vor- und Nachteile im Sachzusammenhang.

Version 1 ZENTRAL

  • Spiel steuert alles – Spieler bleibt schlank
  • Assoziation: Spiel hat in jeder Runde Zugriff auf beide Spieler
  • Sieger als Objekt – Name und alle Daten abrufbar
  • Doppelte Attribute S01/S02 → Redundanz
  • Nicht erweiterbar: 3. Spieler = neue Attribute und Methoden

Version 2 VERTEILT

  • Punkte liegen dort, wo sie hingehören (hohe Kohäsion)
  • Kein doppelter Code, mehr Spieler denkbar
  • Ohne Assoziation kann sich Spiel die Spieler nicht merken – rundeStarten() hat keinen Zugriff
  • Setter für Punkte schwächen die Kapselung
  • Sieger nur als String – das Objekt geht verloren
Aufgabe d · Entscheiden & Dokumentieren

Entscheidung: Version 1.

GEWÄHLT
Version 1

Vollständig und konsistent: Das Spiel kennt beide Spieler in jeder Runde. Für genau zwei Spieler ist die Redundanz vertretbar.

KLASSE SPIEL
Spiel()erzeugt zwei Spieler, setzt Namen und alle Zähler auf 0
spielStarten()setzt Runde und Rundenpunkte zurück, startet beide Spieler neu
rundeStarten()vergleicht die Symbole, vergibt den Rundenpunkt
siegerErmitteln()liefert den Spieler mit 2 Punkten, sonst null
KLASSE SPIELER
symbolUebermitteln(p)speichert das Symbol, erhöht die Runde
symbolWaehlen()liest das Symbol per Scanner ein (Ergänzung)
Aufgabe e · Implementieren

Das Herzstück: rundeStarten()

SPIEL.JAVApublic void rundeStarten()
{
    runde = runde + 1;
    String s1 = spieler01.getAktSymbol();
    String s2 = spieler02.getAktSymbol();

    if (s1.equals(s2))
    {
        System.out.println("Runde " + runde + ": Unentschieden");
    }
    else if ((s1.equals("Stein") && s2.equals("Schere"))
          || (s1.equals("Schere") && s2.equals("Papier"))
          || (s1.equals("Papier") && s2.equals("Stein")))
    {
        rundenpunkteS01 = rundenpunkteS01 + 1;  // Spieler 1 gewinnt
    }
    else
    {
        rundenpunkteS02 = rundenpunkteS02 + 1;  // Spieler 2 gewinnt
    }
}
